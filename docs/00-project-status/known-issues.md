# 已知问题与风险

- 文档更新时间：2026-07-13

## ISSUE-001 服务端访问注册页面可能被 Cloudflare 限制

- 状态：已缓解，仍需持续观察
- 现象：页面可能返回 `Blocked due to abusive traffic patterns`，随后找不到邮箱注册按钮或输入框。
- 原因：服务器出口 IP、浏览器环境或请求行为被目标站点风控。
- 当前处理：使用代理池、节点测活、原生浏览器点击和更清晰的注册日志。
- 后续方向：记录失败页面快照，并按目标站点验证代理，而不是只验证普通连通性。

## ISSUE-002 代理节点可能对 Grok 接口出现瞬时网络失败

- 状态：已缓解
- 现象：模型测试偶发返回网络状态 `0`，随后相同请求又成功。
- 当前处理：模型、测试和额度请求会验证目标地址，并在指定网络错误下重新选择代理，最多重试三次。
- 风险：手动固定代理时仍可能反复使用同一节点，需要用户切换节点。

## ISSUE-003 随机代理模式下注册并发受到共享出口限制

- 状态：设计约束
- 原因：当前 Mihomo 的 `PROXY_POOL` 选择器是进程间共享的全局出口。
- 影响：多个注册线程同时切换随机节点可能互相覆盖选择。
- 当前处理：随机代理模式将注册并发限制为一个。
- 后续方向：如需真正并行，需要为每个工作线程分配独立端口或独立 Mihomo 实例。

## ISSUE-004 没有 CPA 凭证的账户无法查询模型

- 状态：预期行为
- 现象：成功账户显示“需先获取 CPA”。
- 原因：模型接口需要 CPA access token。
- 处理方式：先执行单账户“获取 CPA”或“一键补全缺失 CPA”。

## ISSUE-005 过期 access token 已支持手动安全刷新

- 状态：已缓解
- 现象：CPA access token 过期后，刷新模型或测试模型可能返回未授权。
- 当前处理：成功账户提供“刷新凭证”按钮，优先使用 refresh_token，通过模型验证后原子回写；失败时自动执行完整 OIDC 重取。
- 安全保护：refresh_token 路径在验证前不覆盖旧文件；OIDC 重取验证失败时恢复旧文件。
- 剩余限制：模型测试收到未授权时不会自动启动凭证刷新，仍需要用户点击“刷新凭证”。

## ISSUE-006 “刷新额度状态”不是增加上游额度

- 状态：说明项
- 说明：该操作重新测试账户下的模型并读取限流状态，用于更新本地展示。
- 限制：它不会绕过上游限制，也不会让 xAI 服务器增加账户额度。

## ISSUE-007 OIDC 兜底仍可能受到 Cloudflare 风控影响

- 状态：设计风险
- 触发条件：refresh_token 已失效，需要重新执行完整 SSO/OIDC 获取。
- 影响：兜底流程需要访问账户授权页面，可能遇到 Cloudflare 或代理节点风控。
- 当前处理：优先使用不需要浏览器的 refresh_token；只有快速刷新失败时才进入 OIDC。
- 安全保护：兜底失败不会永久覆盖原有凭证文件。
