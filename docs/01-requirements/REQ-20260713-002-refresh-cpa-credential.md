# REQ-20260713-002 已有 CPA 凭证安全刷新

## 基本信息

- 状态：已完成
- 创建日期：2026-07-13
- 提出来源：用户
- 对应变更：CHG-20260713-002

## 背景

账户已经存在 CPA 文件时，补全任务会按文件是否存在直接跳过。但文件存在不代表其中的 access token 仍然有效。失效凭证可能返回 `Invalid or expired credentials` 或上游 `PermissionDenied`，页面此前没有重新获取入口。

## 需求内容

1. 已有 CPA 的成功账户显示“刷新凭证”按钮。
2. 优先使用现有 refresh_token 获取新 access token，避免不必要的浏览器授权。
3. Token 刷新请求必须使用当前代理配置。
4. 新 Token 必须通过模型权限验证后才能覆盖旧凭证。
5. refresh_token 失效时自动执行完整 SSO/OIDC 重取。
6. 完整重取失败时保留或恢复旧凭证文件。
7. 刷新过程在任务中心展示关键日志。

## 范围

### 包含

- 单账户手动刷新。
- refresh_token OAuth 刷新。
- SSO/OIDC 自动兜底。
- 新凭证模型探测。
- 原子写入与旧文件恢复。

### 不包含

- 自动扫描全部失效凭证。
- 批量刷新所有账户。
- 模型测试返回未授权时自动触发刷新。
- 绕过账户授权或 Cloudflare 验证。

## 验收标准

1. 已有 CPA 的账户显示“刷新凭证”按钮。
2. 点击按钮后显示明确确认信息。
3. refresh_token 有效时不启动浏览器即可完成刷新。
4. 新凭证验证成功后才替换旧文件。
5. refresh_token 失败时任务日志明确显示进入 OIDC 兜底。
6. 兜底失败后旧凭证文件仍然存在。
7. 刷新成功后模型测试返回成功状态。

## 约束与风险

- refresh_token 可能被上游撤销或轮换。
- OIDC 兜底仍可能受到代理或 Cloudflare 风控影响。
- 手动刷新期间不能同时启动其他注册或 CPA 任务。
