# ADR-20260713-001 模型探测强制代理并使用独立缓存

## 基本信息

- 状态：已采用
- 决策日期：2026-07-13
- 影响模块：Web 后端、CPA 探测、代理池、账户页面

## 背景

账户页面需要频繁展示模型信息，但每次刷新账户列表都直接请求上游会造成延迟、额外流量和风控风险。同时服务器直连 Grok 接口不稳定，模型测试必须使用代理。

## 候选方案

### 方案一：每次加载账户列表时实时请求上游

- 优点：数据始终实时。
- 缺点：账户列表约每两秒刷新，会产生大量上游请求，容易触发限流并拖慢页面。

### 方案二：把模型信息写入 CPA 凭证 JSON

- 优点：无需额外缓存文件。
- 缺点：会改变外部服务使用的凭证格式，增加兼容风险。

### 方案三：按账户使用独立缓存并由用户主动刷新

- 优点：不修改凭证格式，不会随页面轮询重复请求，结果可持久展示。
- 缺点：模型列表不是绝对实时，需要用户主动刷新。

## 最终决定

采用方案三，并要求所有模型、测试和额度状态接口通过应用代理池执行。网络类瞬时错误允许最多重试三次。

## 原因

- 保持 CPA 凭证兼容。
- 避免页面轮询造成上游请求风暴。
- 降低服务器直连被限制的风险。
- 每个账户独立缓存，避免并发写入同一个大文件。

## 后续影响

- 页面展示的是最近一次刷新或测试结果，并显示更新时间。
- 上游模型变化后需要主动刷新。
- 代理关闭时模型相关操作不可用。
- 后续可以增加批量刷新和 Token 自动刷新，但仍应沿用独立缓存。
