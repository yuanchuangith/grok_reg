# ADR-20260713-002 refresh_token 优先、OIDC 兜底与验证后替换

## 基本信息

- 状态：已采用
- 决策日期：2026-07-13
- 影响模块：CPA 凭证、OAuth、Web 任务、代理池

## 背景

失效 CPA 凭证需要重新获得可用 access token。直接删除旧文件再重新获取存在数据丢失风险；每次都启动浏览器授权又会增加时间和 Cloudflare 风控概率。

## 候选方案

### 方案一：删除旧文件后执行完整 OIDC

- 优点：实现简单。
- 缺点：失败时旧凭证丢失，且每次都需要账户授权页面。

### 方案二：只支持 refresh_token

- 优点：速度快，不需要浏览器。
- 缺点：refresh_token 被撤销或过期后无法恢复。

### 方案三：refresh_token 优先，失败后 OIDC 兜底

- 优点：正常情况下快速刷新，异常情况下仍可重新授权。
- 缺点：流程和错误处理更复杂。

## 最终决定

采用方案三。refresh_token 返回的新凭证先通过模型权限探测，成功后再原子替换旧文件。refresh_token 失败时进入完整 OIDC；OIDC 结果验证失败时恢复旧文件。

## 原因

- 减少浏览器和 Cloudflare 依赖。
- 支持 refresh_token 轮换。
- 避免失败流程破坏现有凭证文件。
- 复用已有 SSO/OIDC 能力，不增加新的授权绕过方式。

## 后续影响

- 刷新按钮启动的是后台任务，刷新期间不能同时运行其他注册任务。
- Token 刷新、模型探测和 OIDC 均遵循当前代理配置。
- 后续批量刷新应复用相同安全流程，并限制并发。
- 如需自动刷新，应先识别明确的未授权错误，避免无意义地重复授权。
