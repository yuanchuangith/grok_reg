# Project Instructions

## File references

- Refer to project files with editor-friendly local locations such as `web_dashboard.py:326`.
- Do not use browser-opening links for project files.

## Development documentation

- The project has only one development context document: `docs/README.md`.
- Before starting non-trivial development, read `docs/README.md` completely to understand the project tree, current capabilities, recent changes, deployment state, and known issues.
- Do not automatically archive ordinary discussion, implementation details, or temporary debugging results.
- Only update `docs/README.md` when the user explicitly asks to “写入开发文档”, “记录本次需求”, “记录本次变更”, or gives an equivalent instruction.
- When recording, append or update concise entries in the existing sections. Do not create separate requirement, change, deployment, decision, index, status, or template documents.
- Keep enough context for a future developer to understand what changed, why, current deployment status, important constraints, and remaining problems.
- Never write passwords, private keys, access tokens, subscription URLs containing tokens, proxy credentials, or complete account credentials into documentation.
