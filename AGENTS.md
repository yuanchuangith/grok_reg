# Project Instructions

## File references

- Refer to project files with editor-friendly local locations such as `web_dashboard.py:326`.
- Do not use browser-opening links for project files.

## Development documentation

- The documentation entry point is `docs/README.md`.
- Before starting non-trivial development, read `docs/README.md`, `docs/00-project-status/current-status.md`, and `docs/00-project-status/known-issues.md`, then open the requirement, design, or change documents relevant to the task.
- Do not automatically archive ordinary discussion, implementation details, or temporary debugging results.
- Only write a requirement, change record, deployment record, or decision record when the user explicitly asks to “写入开发文档”, “记录本次需求”, “记录本次变更”, or gives an equivalent instruction.
- When recording, update the corresponding index and create the detailed document from the matching template.
- A requested documentation update must also refresh the current status, known issues, and progress log when they are affected.
- Keep requirements and implementation changes separate. A request describes what is wanted; a change record describes what was actually delivered.
- Never write passwords, private keys, access tokens, subscription URLs containing tokens, proxy credentials, or complete account credentials into documentation.
